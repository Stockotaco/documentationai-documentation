## Overview

This changelog is a starter kit template for Bridge documentation. Use it to track releases, explain behavior changes, and call out upgrade notes in a way that is easy to scan.

Keep entries short, factual, and dated. Focus on what changed, why it matters, and whether users need to take action.

## Release workflow

Use a repeatable process so each release note stays consistent. This helps your team publish updates quickly and makes the page easier to maintain over time.

<Steps>
  <Step title="Write the summary" icon="book-open">
    Start with one sentence that explains what changed. Keep it concrete and avoid vague language.
  </Step>
  <Step title="Group the changes" icon="settings">
    Split the release into sections such as New Features, Improvements, Bug Fixes, and Upgrade Notes.
  </Step>
  <Step title="Verify the date" icon="check-circle">
    Use an ISO date like `2026-11-04` so releases sort correctly and remain easy to compare.
  </Step>
  <Step title="Publish and review" icon="rocket">
    After publishing, scan the entry on desktop and mobile to confirm that headings, spacing, and lists render cleanly.
  </Step>
</Steps>

## What to include in each release

Use the checklist below to keep your updates useful and consistent.

| Topic | What to write |
|------|---------------|
| Recent releases | The latest version numbers and dates |
| New features | New capabilities users can try right away |
| Bug fixes | Problems that were corrected in the current release |
| Behavior changes | Changes in defaults, ordering, or interaction patterns |
| Upgrade notes | Any action users should take after updating |

<Expandable title="Style guidance for release notes" default-open="false">
  
Write in active voice and keep each bullet specific. Avoid hype, avoid vague claims, and mention user impact when it matters.

Good example:

- Reduced page load time on the changelog view.
- Fixed a broken anchor link for older releases.

Less useful example:

- Improved everything.
- Made the product better.

</Expandable>
